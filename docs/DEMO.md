# Проверка перед защитой

1. Запустить приложение по README, создать первого администратора через CLI и второй аккаунт через раздел «Администрирование». Убедиться, что второй не видит чужой анализ до предоставления доступа.
2. Загрузить `ЗАДАНИЕ.zip` через «Датасеты». В библиотеке создать или загрузить `.py` для нормализации, сравнения, агрегации и проверки. Начальные примеры используют штатные функции; изменить параметр или преобразование.
3. Создать анализ: набор, процедуры, проверки, параметры. Сохранить шаблон. Пока расчёт идёт, обновить страницу и открыть код этапа из журнала.
4. На исходном открытом наборе проверить 2002 заявки, 502 с изменениями и 385 смен решений. При наличии отложенного набора ожидаются 998 заявок, 248 с изменениями и 186 смен решений. Материалы организаторов не включаются в репозиторий.
5. В сводной открыть раскладку «До / после»: строки `PATH` и `ADJUSTED_VALUE`, колонки `DIFF_FLAG`, `SOURCE`, показатель уникальных заявок. Перетащить поле между осями, показать окно «Поля» и раскладку «Структура ответа» из прототипа; таблица пересчитывается автоматически. Из числа открыть заявку и только атрибуты выбранной ячейки. Кнопкой показать всю заявку и исходный JSON.
6. Открыть результаты пяти штатных проверок. Добавить собственную проверку из редактора в готовый отчёт и показать новую строку без повторной нормализации.
7. Скачать HTML, открыть его и перейти по ссылке в сводную. Показать мягкую подсветку LOW и код проверок под раскрытием.
8. При доступной Ollama запросить мнение ИИ; автоматический запрос включается при создании анализа. После добавления проверки старое мнение помечается устаревшим.
9. Показать настройки доступа и совместный просмотр вторым аккаунтом. Наблюдатель не получает права на редактирование или согласование.
10. Назвать оборудование, время обработки и время действий в браузере. Различать длительность нормализации, полного расчёта и открытия отчёта; не выдавать локальный замер за гарантию на любом оборудовании.

Для сдачи исходников: `python3 scripts/package_source.py`. Архив содержит приложение, инструкции, тесты и lock-файлы; рабочие аккаунты, данные и материалы организаторов исключены. Этот архив можно распаковать в пустой репозиторий и опубликовать на выбранном Git-сервисе.
