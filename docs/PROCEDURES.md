# Контракт процедур

В библиотеке четыре отдельных раздела: «Разбор и нормализация» (`normalization`), «Сравнение» (`comparison`), «Подготовка отчёта» (`aggregation`) и «Проверки». При переключении разделов несохранённый код остаётся в редакторе до ухода со страницы.
Откройте «Настройка анализа», выберите датасет и нужный этап в верхней панели. Внутри этапа доступны «Стандартная», «Из библиотеки» и «Свой Python». Выберите сохранённую процедуру либо нажмите «Открыть код»: измените Python или загрузите `.py`, затем нажмите «Сохранить и применить». Все четыре этапа, включая проверки, настраиваются на одном экране. Библиотека остаётся каталогом для повторного использования. Сохранённый файл можно выбрать повторно. Изменение библиотеки не меняет уже созданные запуски: код, параметры и базовые функции копируются в запуск.

Каждый файл экспортирует `PROCEDURE = {"entrypoint": run}`. Дополнительные параметры задаются в `PROCEDURE.params`, библиотеке и конфигурации запуска; последнее значение имеет приоритет. У процедур отдельные лимиты времени и памяти; общая отмена расчёта завершает и процедуру.

## Нормализация

```python
def run(document, app_id, source, config, params):
    return defaults.normalize(document, app_id, source, config)

def segments(app_id, before, after, config, params):
    return defaults.segments(app_id, before, after)

PROCEDURE = {"entrypoint": run, "segments": segments}
```

`run` вызывается для каждого документа, `source` — `BEFORE` или `AFTER`. Возвращается список или генератор объектов с колонками `APP_ID, SOURCE, PATH, PREFIX, CLASS, SUFFIX, ARRAY_KEY, KEY, VALUE, VALUE_TYPE, ADJUSTED_VALUE`. Все значения строковые. `VALUE_TYPE`: `string`, `number`, `boolean`, `null`. Отсутствующий атрибут не создаёт строку; `null` создаёт строку со значением `NULL` и типом `null`. Пара `(PATH, ARRAY_KEY)` внутри заявки и среза уникальна. Нельзя подменять `APP_ID` или `SOURCE`.

`segments` возвращает `APP_ID`, `DECISION_CHANGED` (0/1), пары полей `DECISION`, `PD_MODEL`, `TOP_OFFER`, `CUTOFF`, `REJECT_REASON`, `SCORE_OKB` с окончаниями `_BEFORE`/`_AFTER`, а также `PRODUCTS`, `PARTNER_TYPE`, `ROUTING_METHOD`. Неизвестные значения допускают `None`. `PRODUCTS` — идентификаторы через `;`. Опциональный `PRODUCT_CONTEXT` содержит JSON-строку массива контекстов продуктов.

В базовой нормализации доступны `exclude_paths`, `arrays`, `buckets` и `layout`. Пример настройки структурных колонок учебного массива:

```json
{"layout":{"company.rejectReasons":{"CLASS":"rejectReasons","SUFFIX":"reason","KEY":""}}}
```

`layout` переопределяет только `PREFIX`, `CLASS`, `SUFFIX`, `KEY`; техническая идентичность `PATH + ARRAY_KEY` сохраняется. Для скалярного массива в режиме `value` базовый `KEY` уже пустой. Процедура может произвольно преобразовывать документ и формировать строковые бакеты, сохраняя исходный `VALUE` для сравнения.

## Сравнение

```python
def run(data, params):
    for row in data.default_comparison():
        yield row
PROCEDURE = {"entrypoint": run}
```

Доступны потоки `data.normalized()`, `data.segments()` и стандартное сопоставление `data.default_comparison()`.

Выход: `APP_ID, PATH, ARRAY_KEY, PREFIX, CLASS, SUFFIX, KEY, VALUE_BEFORE, VALUE_AFTER, TYPE_BEFORE, TYPE_AFTER, ADJUSTED_BEFORE, ADJUSTED_AFTER, CHANGE_TYPE, DIFF_FLAG`. `CHANGE_TYPE`: `SAME`, `VALUE_CHANGED`, `ATTRIBUTE_NEW`, `ATTRIBUTE_LOST`; `DIFF_FLAG` — 0 для `SAME`, иначе 1. Набор ключей обязан совпадать с объединением нормализованных атрибутов обоих срезов. Пропуски, посторонние атрибуты и дубли приводят к отказу публикации.

## Агрегация

```python
def run(data, params):
    for fact in data.default_facts():
        # Можно изменить группировочное представление значения.
        yield fact
PROCEDURE = {"entrypoint": run}
```

Доступны также `data.comparison()` и `data.default_facts()`. Каждый факт содержит `PATH, PREFIX, CLASS, SUFFIX, KEY, ARRAY_KEY, SOURCE, ADJUSTED_VALUE, CHANGE_TYPE, DIFF_FLAG`, `CNT` и полный список уникальных `APP_IDS`. `CNT` равен длине списка. Ссылки проверяются по заявке, атрибуту и срезу; признаки изменений обязаны соответствовать сравнению. Возвращённые факты непосредственно питают сводную; разрезы заявки присоединяются через полные связи APP_IDS, чтобы индивидуальные скоры и офферы не раздували число хранимых групп. По их связям пересчитываются уникальные итоги: простая сумма всех `CNT` числом заявок не является.

## Проверки и дополнения к отчёту

Контракт проверок — `CHECK = {"entrypoint": run}`, где `run(mart, params)` возвращает строки `LABEL, SOURCE, ARGUMENT, CNT, TOTAL, METRIC, APP_IDS, RESULT, CONFIDENCE`. До 1000 строк, до 500 000 идентификаторов в строке, суммарный результат до 64 МиБ. `APP_IDS` уникальны, принадлежат отчёту и не превышают `CNT`. Для полной детализации возвращайте полный список, а не срез `[:20]`. В JSON отчёта сохраняется компактный предпросмотр, полный список хранится отдельно и доступен с пагинацией.

В редакторе можно выполнить пробу или добавить результат в общий отчёт. Добавление атомарно увеличивает редакцию отчёта, сохраняет прежние строки, код и параметры, помечает старое мнение ИИ устаревшим и возвращает согласованный анализ на рассмотрение. Исходная витрина при этом не пересчитывается.

Python выполняется в отдельном процессе с Landlock и seccomp. Разрешены входы выбранного этапа и библиотеки среды; закрыты посторонние файлы, сеть, создание процессов и произвольная запись. Процедуры возвращают данные через подготовленные выходные потоки. Диагностика ошибки сохраняется в задаче. Из журнала можно открыть исполненный код этапа и снимок его базовых функций.

## Предварительная проверка

Редактор CodeMirror 6 поддерживает Python, отступы, сворачивание, поиск, подсказки контрактов и переход к строке ошибки. Контракт каждого этапа оформлен в интерфейсе как документация: сигнатура, входы и поля результата. Для проверки в библиотеке, настройке запуска и готовом отчёте используется один общий компонент; методы `mart` описывают различие количества строк и уникальных заявок. Он загружается локально вместе с приложением, без CDN. API `POST /api/code/validate` принимает `{stage, code}` и возвращает `{valid, diagnostics, scope: "static"}`. Анализ выполняется автоматически после изменения кода; устаревший ответ не заменяет результаты для нового текста.

Проверяются синтаксис Python, экспорт `PROCEDURE`/`CHECK`, вызываемость явно заданной точки входа, совместимость числа позиционных аргументов, обязательный `segments`, отсутствие `async` и явно неправильные возвращаемые значения. Для непосредственно возвращаемых литералов строк проверяются обязательные поля и перечисления. Код не исполняется при этой проверке. Динамически собираемые экспорты и сигнатуры отмечаются предупреждением, а не объявляются полностью проверенными.

`POST /api/runs/validate` проверяет доступность датасета, версии и владение процедурами/проверками, параметры и контракты выбранных обработчиков, не создавая запуск или задачу. Изменение формы сбрасывает результат проверки. Неприменённый код, ошибка или недоступность предварительной проверки блокируют кнопку запуска. Сервер повторяет проверку пользовательского кода при создании запуска, сохранении и добавлении проверки в готовый отчёт; старые сохранённые некорректные процедуры также отклоняются.

Статический анализ не доказывает корректность произвольного Python и не проверяет результаты на датасете. Фактические типы строк, уникальность, полнота идентификаторов и согласованность counts по-прежнему проверяются при выполнении в изолированном процессе. Полноценного Jupyter kernel с ячейками нет.
